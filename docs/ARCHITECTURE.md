# GameRssReader — アーキテクチャ概要 (クリーンアーキテクチャ)

目的: 将来的な拡張（別 UI、ブラウザ差し替え、テスト容易性）を想定し、ドメインとインフラ/UI を明確に分離します。

ディレクトリ構成（現在の初期実装）

- `gamer/`
  - `domain/` — エンティティ（`Article`）やユースケース（今後）
  - `ports/` — インターフェース（例: `RSSProvider`）
  - `adapters/` — `requests` / BeautifulSoup を使った実装（ネットワーク・RSS パーサ）
  - `ui/` — GUI 実装（`tk_app.py` などに今後移行）

進め方（短期）

1. まずは `main.py` を壊さず、ネットワーク/解析ロジックを `adapters` に移行しました。これによりビジネスロジックと副作用の分離が容易になります。
2. 次はユースケース層（`domain/usecases.py`）を作り、UI はそのユースケースに依存する形へ移行します。

今後のタスク

- `domain/usecases.py` の作成
- `ui/tk_app.py` へ `main.py` の UI を段階移行
- `adapters` のブラウザ抽象化（CEF / pywebview のラッパ）
- ユニットテスト追加（ports をモックしてテスト可能）

開発者メモ

- 既存の機能はそのまま動作するはずですが、追加のリファクタを行うたびに `main.py` の動作確認を行ってください。
- 依存注入は最初は手動（`app.py`）で行い、後で DI コンテナ導入も検討してください。
